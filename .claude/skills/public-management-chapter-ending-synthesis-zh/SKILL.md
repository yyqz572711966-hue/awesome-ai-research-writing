# 公共管理章节结尾综合段 Skill

## Purpose

用于生成公共管理、行政管理、政策研究、基层治理、政府治理等中文论文中的章节结尾综合段。重点是把本章已有论述自然收束，并为下一章铺垫，不写成机械总结，也不堆砌空泛口号。

## When to use

当用户提出以下需求时使用本 skill：

- 写某一章末尾的总结段、过渡段或小结段
- 将一章中的若干小节内容整合成一段自然收束文字
- 为下一章的问题分析、原因分析、路径建议或制度设计做衔接
- 优化公共管理论文中显得突兀、模板化、AI 味明显的章节结尾
- 将分散要点改写成正式、连贯、适合 Word 论文正文的段落

## Inputs

优先读取用户提供的以下信息：

- 论文题目
- 当前章标题
- 当前章下属二级或三级标题
- 本章核心观点或已有正文
- 下一章标题或下一章将要展开的内容
- 用户指定的写作风格、字数和是否需要学术化

如果用户没有提供完整信息，可以根据已有标题和正文推断，但不得虚构具体数据、政策文件或案例事实。

## Writing principles

1. 收束本章

先概括本章完成了什么论证任务。不要逐条复述标题，也不要写成“本章首先、其次、最后”的机械句式。应当提炼本章共同指向的问题、机制或判断。

2. 提炼公共管理含义

章节结尾不能只停留在现象层面。应当适度提升到公共管理论文常见的分析层次，例如治理主体、政策执行、资源配置、组织协调、制度安排、基层治理能力、行政责任、公众参与、绩效评价等。

3. 保持克制

避免使用过大的表达，例如“构建现代化治理体系”“实现国家治理能力现代化”等，除非正文确实围绕这些内容展开。优先使用具体、稳妥、可承接的表达。

4. 自然过渡

如果下一章是问题分析，结尾应当引出尚待解释的现实困境。如果下一章是原因分析，结尾应当指出表层表现背后的成因需要进一步展开。如果下一章是对策建议，结尾应当转向治理改进的必要性。

5. 语言要求

使用规范中文学术表达，适合直接放入 Word 论文正文。不要使用 Markdown 加粗、列表或标题符号。避免口语化、宣传化和过度排比。句子应当清楚、稳定，不要写得太绕。

## Workflow

第一步，识别章节功能。
判断当前章节是概念界定、理论基础、现状分析、问题表现、原因分析、经验借鉴还是对策建议。

第二步，提炼章内主线。
从标题和正文中归纳本章共同服务的中心判断，删去重复要点。

第三步，确定衔接方向。
根据下一章内容选择过渡方式。没有下一章信息时，只完成本章收束，不强行铺垫。

第四步，生成正文。
通常输出 1 段，字数控制在 150 至 300 字。用户另有要求时按用户要求处理。

第五步，自查。
检查是否存在空泛口号、机械罗列、无依据扩展、重复前文、AI 味明显等问题，并立即修正。

## Output format

默认只输出可直接放入论文的正文段落，不额外解释写作思路。

如果用户要求说明修改逻辑，可在正文后补充“修改说明”，但正文必须放在最前。

## Example trigger prompts

- 帮我写这一章的结尾综合段
- 这一章怎么自然过渡到下一章
- 帮我把这几个小标题整合成章节小结
- 这段结尾太像 AI，帮我改得自然一点
- 用公共管理论文的表达方式收束这一章

## Quality checklist

输出前确认以下事项：

- 是否围绕当前章标题展开
- 是否没有虚构事实和文献
- 是否避免了空泛口号
- 是否能自然接到下一章
- 是否适合直接粘贴进中文论文正文
