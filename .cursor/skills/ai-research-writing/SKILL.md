# AI Research Writing Skill

## Purpose
帮助研究人员快速生成、翻译、润色学术论文，提供完整的 Prompt 库与实验分析工具。用户无需记忆复杂 prompt，直接说明需求，系统自动调用相应模板。

## When to use
- 需要翻译中英文论文片段（LaTeX 或 Word）
- 需要润色论文表述、去除 AI 味
- 需要生成论文图表、标题、表格
- 需要实验数据分析与可视化建议
- 需要从 Reviewer 视角审视论文质量
- 需要逻辑检查与学术规范审视

## Inputs
- **论文文本**：中文/英文片段，支持 LaTeX、Word、Markdown 格式
- **实验数据**：Excel/CSV/文本表格，包含方法名、指标、数值
- **论文元信息**：目标会议（ICML/NeurIPS/ICLR/ACL）、当前草稿版本
- **修改指令**：简短的修改意图（如"压缩长度""增强学术感""去 AI 味"）

## Workflow

### 第一步：理解用户需求
识别用户的核心任务：
- **翻译类**：中→英、英→中
- **润色类**：表达优化、AI 味检测、逻辑检查
- **生成类**：图表推荐、标题生成、表格制作
- **分析类**：实验结论提取、Reviewer 视角审视

### 第二步：调用核心 Prompt 模板
根据需求，从下方 Prompt 库中选择最匹配的模板。用户无需手动复制，系统直接应用。

### 第三步：严格执行模板规范
- **保留原有格式**：LaTeX 特殊字符转义、Word 纯文本输出、Markdown 禁用
- **多部分输出**：通常包含「Part 1 正文/代码」、「Part 2 中文翻译」、「Part 3 修改日志」
- **质量检查**：完成后自查逻辑完整性、信息准确性、格式规范性

### 第四步：迭代优化
根据反馈进行多轮修改，直到用户满意。

   - 示例：将"为了解决这一痛点"改为"针对上述问题"；将"展现了令人惊叹的能力"改为"表现出显著的性能提升"。

2. 句式与结构自然化：
   - 消除长定语：避免英式长定语结构（如"一个...的...的..."），拆分为短句。
   - 限制被动语态：用主动语态或无主语句替代。
   - 灵活处理列表：应尽量避免机械的"首先...其次...最后..."，融合成逻辑连贯的段落。

3. 修改阈值：
   - 宁缺毋滥：如果输入的文本已经严谨自然，请保留原文。

4. 输出格式：
   - Part 1 [正文]：输出重写后的纯文本（如果原文已足够好，则输出原文）。
   - Part 2 [修改日志]：
     * 如果进行了修改：简要列举删改了哪些无实质信息的表达。
     * 如果未修改：输出 "[检测通过] 原文表达严谨自然，无明显 AI 痕迹，建议保留。"

#### 论文整体审视（Reviewer 视角）
**应用场景**：从审稿人角度对论文进行全面评估，找出问题与改进建议

**用法**：
```
用户说："帮我用审稿人的眼光看一下这篇论文"
系统调用：下述 Prompt，上传 PDF
```

**完整 Prompt**：
````markdown
# Role
你是一位以严苛、精准著称的资深学术审稿人，熟悉顶级会议的评审标准。你的职责是对论文进行客观、全面的评估，既指出潜在问题，也如实肯定贡献。

# Task
请深入阅读并分析上传的【论文文件】。基于投稿目标，撰写一份严格但具有建设性的审稿报告，重点检查：
1. 论点是否清楚
2. 规范依据是否准确
3. 案例材料是否足够
4. 概念使用是否混乱
5. 哪些地方可能被老师质疑

# Constraints
1. 评审基调：
   - 客观评估论文的实际水平，精准定位其不足。
   - 区分"真正致命的问题"与"可以在修订期内解决的小问题"。
   - 评分须忠实反映论文的实际水平。

2. 审查维度：
   - 社区贡献：是否为领域带来了实质性推进？
   - 严谨性：核心主张是否有充分的实验支撑？Baseline 是否齐全、版本是否对齐？消融实验是否覆盖了关键设计决策？
   - 一致性：引言中声称的贡献在实验部分是否真正得到了验证？

3. 输出格式：
   - Part 1 [审稿意见]（中文）：
     * Summary：一句话总结
     * Strengths：1-3 点贡献
     * Weaknesses (Critical)：主要问题，具体到实验设置、论证环节或表述缺陷
     * Rating：预估评分（1-10）与依据
   - Part 2 [改稿建议]（中文）：
     * 问题根源：每条 Weakness 的深层原因
     * 可救性判断：哪些可以修订，哪些属于结构性缺陷
     * 行动指南：具体建议补充哪些实验、重写哪段逻辑

# Input
请上传论文 PDF，并指定投稿目标（如 ICML 2026）
````

## 技巧与最佳实践

### ✅ 做这些事
- **明确说出需求**：「帮我翻译」vs 「帮我翻译这段，要投 NeurIPS，注意保持 LaTeX 纯净」后者更精准
- **一次只用一个 Prompt**：避免混合使用，结果会混乱
- **提供足够上下文**：包括目标会议、论文主题、预期风格
- **迭代修改**：如果第一轮结果不满意，直接说"不够正式"或"太复杂了"，系统会自动调整

### ❌ 不要做这些事
- **随意修改 Prompt**：Prompt 经过精心设计，任何修改都可能破坏逻辑
- **一次性处理整篇论文**：分段处理效果更好，也更容易迭代
- **混合多个需求**：不要在一条指令中同时要求"翻译+润色+图表推荐"
